## Installation

The update check below needs the previous release installed with the same
signing key. A device that still has a 1.4.3 build signed with the standard
debug key can take the 1.4.4 debug-signed CI APK with `adb install -r`, keeping
History. If the installed app uses the release or F-Droid signing key instead,
uninstall it first. This clears History, and the update check then stays NOT
VERIFIED on the device. Record which procedure was used. Do not substitute the
debug or Link Check variant for the CI release APK.

**Result:** the tablet had the debug-signed 1.4.3 APK from `38581db`
(`a617f96d…`, same debug certificate). The 1.4.4 debug-signed APK was installed
over it with `adb install -r` as a normal, non-incremental install. History was
kept (owner-reported).

The codec timing below uses the **Link Check** app (`unfurlit-link-check-apk`
from the same CI run). It installs next to the release app, with its own
History. Never install the debug build for it: it has the release app's package
name, so installing it over a differently signed release means uninstalling the
release first, which deletes its History.

### Tablet codec timing, for deciding fix (b)

Fix (b) would prefer codecs the device decodes in hardware. Decide it from the
tablet's numbers with 1.4.4's ranged requests, so that slow downloads no longer
hide decoding time. Install the Link Check app (see Installation), then, with
`SERIAL` from `adb devices`:

```bash
adb -s SERIAL logcat -c
adb -s SERIAL logcat -s PlaybackTiming:I | tee tablet-timing.log
```

Share each link to **Unfurlit Link Check** and wait 35 seconds after the video
starts before the next: [youtube-big-buck-bunny](https://www.youtube.com/watch?v=aqz-KE-bpKQ)
(1080p60), [youtube-video](https://www.youtube.com/watch?v=eRsGyueVLvQ) and
[youtube-short-link](https://youtu.be/jNQXAC9IVRw) (240p). This times the app's
own format choice only. Each video logs its decoder and whether it is
hardware-accelerated, `ready`, `first frame`, and a `report` line with rendered
and dropped frames.

| Video | Decoder (hardware?) | Ready (ms) | First frame (ms) | Dropped / rendered frames in 30 s |
| --- | --- | --- | --- | --- |
| youtube-big-buck-bunny | `c2.android.av1.decoder` (software) | 769 | 726 | 0 / 1791 |
| youtube-video | `c2.android.av1.decoder` (software) | 719 | 705 | 19 / 1771 |
| youtube-short-link | `c2.android.av1.decoder` (software) | 262 | 226 | 0 / 284 |

## Findings

- **Extraction takes 16–18 s on the tablet**, whether the Python process is
  running already or not, against about 2.4–3.3 s for the same links on a desktop.
  yt-dlp 2026.08.19 (1.4.3) and 2026.10.21 (1.4.4) take the same time on the
  desktop, so this is not a 1.4.4 regression. It is open for a later release.
- **A long pause in the background ends the media session.** About 12 minutes
  after Sintel was paused with the app in the background, Media3 took the
  playback service out of the foreground, and a minute later Android stopped it
  as idle. The notification and the lock-screen and headset controls went with
  it, though the paused player stayed in the stopped activity. Playback can only
  be resumed by reopening the app. Because the session is published only when a
  player is attached, the service probably does not start again for that player,
  so background audio after such a resume may lack its foreground service. This
  is not new in 1.4.4 and is not yet confirmed on a device.

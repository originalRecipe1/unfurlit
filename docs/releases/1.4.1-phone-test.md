## Installation and comparison

1. Before uninstalling 1.4.0, open the same links below and note perceived loading
   speed so the comparison is meaningful on the same phone and connection.
2. Uninstall 1.4.0. This removes its local History. The debug signing certificate
   differs from the published release certificate, so this phone test uses a
   fresh installation.
3. Install the debug-key-signed **merge CI release APK** supplied by the agent,
   using the single `adb install` command in the handoff. No keystore operation
   is required from the owner. Do not substitute a locally rebuilt APK.
4. Open **only `youtube-video` once**, then record Android Settings storage below
   before testing the remaining links. Record user data excluding cache and
   record cache separately if the Settings screen combines them.
5. Complete the link, speed and History checks, then record any additional checks
   from the [reusable pre-release checklist](../development.md#pre-release-phone-checklist).

The 1.4.0 → 1.4.1 upgrade check is performed **on API 30 and API 36 x86_64
emulators, not on this phone**. See [the emulator record](1.4.1-emulator-test.md)
for actual release-install, retained History/thumbnail and runtime-replacement
evidence. A clean phone install does not verify upgrading the physical device.

## After the owner merges: APK handoff and publication

1. Record the full merge SHA. Wait for **Android CI** on that exact SHA to pass;
   download its `unfurlit-unsigned-release-apk` artifact and record the original
   `app-release-unsigned.apk` SHA-256 above.
2. The agent zipaligns that file and signs a copy using the standard Android
   debug keystore (`androiddebugkey`), then verifies its signature/alignment and
   records the signed hash. Supply `Unfurlit-1.4.1-phone-test.apk` and one command:
   `adb install /path/to/Unfurlit-1.4.1-phone-test.apk` (replace with the supplied
   file's actual path). The owner first uninstalls 1.4.0 as described above.
3. After the phone test passes, commit the completed record separately without
   changing the tested release source. In **Actions → Publish release tag →
   Run workflow**, select `main` and enter the **same full tested merge SHA** in
   `release_commit`. Check that this SHA is the one recorded above. The workflow
   checks out, builds and tags that commit, even if `main` has advanced.
4. The workflow runs release tests/lint, builds, and signs with the existing
   repository secrets; it creates `v1.4.1` and uploads the release APK, checksum
   and R8 mapping. The owner does not supply or operate release keys.
5. Verify the tag resolves to the tested SHA and check the published APK. Only
   then replace the F-Droid draft commit placeholder, rerun the build/scans with
   the published binary and allowlisted signer, and prepare the MR update for
   posting under separate authorization.
